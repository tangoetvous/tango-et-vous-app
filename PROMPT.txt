Contexte du projet

Tu travailles sur le système numérique de Tango & Vous, une école de tango argentin à Paris dirigée par Florencia García et Jérémy Braitbart (tangoetvous@gmail.com / tangoetvous.com), association Le Regard Se Pose.

Stack technique (tout gratuit/existant)
- Google Sheets = base de données centrale
- Google Apps Script (Code.gs) = API backend (Web App déployée)
- GitHub Pages = hébergement PWA
- Firebase Authentication = connexion sans mot de passe (lien email)
- Cloudinary = upload médias (preset "tango_uploads")
- Wix = site public (iframes)
- AssoConnect = paiements

Fichiers du projet
Le dossier contient notamment admin.html — le dashboard administrateur de la PWA.

BUG À CORRIGER EN PRIORITÉ

Dans admin.html, la fonction renderValiderPaiement() contient une string JavaScript mal fermée ligne ~1300 :

    +'<div class="box-ok" id="vp-ok">✓ Paiement validé ! L\'élève est maintenant inscrit.</div>'

Le L\'élève ferme prématurément la string JS. Node.js signale : SyntaxError: Unexpected identifier 'élève'. Corriger en remplaçant L\'élève par L&#39;élève ou en passant cette ligne en guillemets doubles.

Après correction, valider la syntaxe JS complète du fichier avec :
    node --check admin.html
ou en extrayant le bloc <script> dans un fichier .js temporaire.

ARCHITECTURE admin.html

L'interface admin est un fichier HTML autonome (sans framework, JS vanilla var/function, zéro onclick inline, zéro prompt()/confirm()). Tout passe par data-action sur les boutons et un handleAction() central, avec bindTabEvents() appelé après chaque render.

8 onglets :
1. Cours Tango — fusion élèves + inscriptions. 6 sous-onglets : Demandes / Demande validée / Attente paiement / Inscrits / Nouvelle demande / Valider paiement. Flux statuts : demande → valide → attente_paiement → inscrit
2. Essai — cours d'essai, trié par date + niveau, fiches partenaires séparées
3. Cartes 10 — 10 points visuels avec dates, pointer/renouveler
4. Stages — 4 sous-onglets par créneau : Technique (14h) / Stage 1 (15h) / Stage 2 (16h30) / Pointage
5. Sorano — suivi adhésion Vincennes, trié par niveau
6. Agenda — liste 12 mois glissants, filtres Cours/Stages/Milongas
7. Publications — avec aperçu, duplication, programmation multiple
8. Login — connexion sans mot de passe (Firebase en prod, démo directe si VOTRE_DEPLOYMENT dans l'URL)

Modals (remplacent prompt/confirm bloqués dans certains contextes) :
- #modal-date — saisie date (remplace prompt())
- #modal-confirm — confirmation (remplace confirm())

RÈGLES DE CODE STRICTES
- JS vanilla uniquement — pas de const/let/arrow functions dans les strings HTML générées
- Zéro onclick inline dans le HTML généré via innerHTML
- Zéro prompt() / confirm() — utiliser les modals ouvrirModalDate() / ouvrirModalConfirm()
- Tous les boutons utilisent data-action="nom-action" + data-id="..." etc.
- bindTabEvents(el) est appelé après chaque renderTab() pour attacher les listeners
- Accolades JS : toujours vérifier l'équilibre ouvertes/fermées après modification
- Apostrophes dans les strings JS simples : utiliser &#39; ou guillemets doubles pour les textes français avec apostrophes
