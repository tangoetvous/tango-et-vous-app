I0 — Notification admin (toute nouvelle inscription)

POST /api/notify/inscription-cours (sans auth)
Destinataire : tangoetvous@gmail.com
Header admin : Fond #111 · bordure or · "Nouvelle inscription [tango/preinscription]"
Sujet : [Inscription tango] ${prenom nom} — ${Ville} ${Niveau} · ${Rôle} · ${statut}
Body : { email, prenom, nom, tel, role, ville, niveau, saison, statut, partenaire?, emailPartenaire?, pPrenom?, pNom?, pRole?, venue?, type }
⚠️ Revérifié le 2026-08-17 — la charge utile réelle du formulaire ne contient ni statut, ni emailPartenaire, ni type (annotation précédente erronée). En revanche deux champs sont bien transmis et jamais lus : mode ('regulier' ou 'preinscription' — c'est lui qui permettrait un email de pré-inscription distinct) et niveau (doublon de c1.niveau).
Encadré or (solo) : Nom/email/tel · Rôle (badge couleur) · Cours · Statut
Encadré or (couple) : isCoupleAdmin = c.venue === 'avec-part' && !!c.pPrenom
→ Bandeau violet #6a1b9a "👫 COUPLE" (pill blanche)
→ Ligne principale fond vert #2e7d32 : Prénom NOM · email · tel · badge Rôle personne (bleu guideur·se / rose guidée)
→ Ligne partenaire fond vert foncé #1b5e20 : Prénom NOM partenaire · badge Rôle inverse
pRoleAdmin = c.pRole || (c.role==='guidee' ? 'guideur' : 'guidee')
2 cours : si 2 cours → 2 encadrés or distincts (avec variante couple si applicable)
Boutons : 📞 tel: · ✉️ mailto: · 💬 sms: · Ouvrir l'admin → Inscriptions Tango

I01 — Guideur ou couple, att. paiement

POST /api/notify/inscription-cours (sans auth)
Déclencheur : statut='attente_paiement' (guideur seul ou couple)
Sujet : Votre demande d'inscription au tango est validée — procédez à votre inscription sur AssoConnect
Variantes : « …au tango en duo est validée… » (couple) · « …au tango à Vincennes est validée… » (Vincennes)
Preheader : "Votre inscription tango est validee - finalisez votre dossier sur AssoConnect"
Bandeau : Vert ✓ "Votre inscription au tango est validée — finalisez votre inscription"
Cours box : Cours · Saison · Rôle · Statut "✓ Att. paiement" · Partenaire (si couple)
Bouton AssoConnect : tev_liens_assoconnect[saison].cours (depuis admin Paramètres)
Sorano : si ville='vincennes' → encadré jaune 🏛 Adhésion Sorano
Quelques précisions : Avertissement 2 emails différents en couple · Modes paiement CB/espèces/chèque
Livret : tev_params_${ville}_${saison}.livret.url_deb / url_int

I01-att — Guidée seule, att. validation

POST /api/notify/inscription-cours (sans auth)
Sujet : Votre demande d'inscription au tango est bien reçue — liste d'attente
Déclencheur : statut='demande' (guidée seule dans tous ses cours)
Preheader : "Votre demande inscription tango enregistree - en attente de validation admin"
Bandeau : Orange ⏳ "Votre demande d'inscription est enregistrée — liste d'attente"
Encadré : Explication parité · 3 options (attente / autre créneau / cours d'essai)
Paragraphe intro : Se termine par "Vous êtes pour l'instant en liste d'attente." en gras — ajouté pour que l'élève comprenne immédiatement son statut
Signature : signWait — "Nous reviendrons vers vous très prochainement." (≠ signEleve — destinataire pas encore confirmé, évite le clipping Gmail)

I03 — Admin valide paiement → inscrit

POST /api/notify/inscription-cours-payee (JWT admin)
Sujet élève : Bienvenue ${prénom} ! Votre place au Cours de Tango ${Niveau} à ${Ville} est confirmée
2 cours → « Bienvenue ${prénom} ! Vos places aux Cours de Tango sont confirmées ». Sujet volontairement différent d'I01/I02 pour éviter que Gmail regroupe les fils et masque le contenu.
Sujet admin : [Inscription tango] ${prénom nom} — ${Ville} ${Niveau} · ${Rôle} · ✓ Inscrit·e
Body : { email, prenom, nom, saison, coursInfos: [{ville, niveau, role}] }
Backward compat : ville, niveau, role au niveau racine si mono-cours (coursInfos absent ou vide)
Sujet (1 cours) : ✓ Votre inscription au tango est confirmée — à bientôt !
Sujet (2 cours) : ✓ Vos inscriptions au tango sont confirmées — à bientôt !
Preheader : "Inscription confirmee ${ville1 label} ${niveau1 label} [+ ${ville2} ${niveau2}] - nous vous attendons avec impatience"
Dynamique — liste les cours inscrits, ASCII sans accents · calculé dans le handler depuis coursInfos
Bandeau : Vert ✓ — "Inscriptions confirmées" au pluriel si 2 cours
Intro : "Votre inscription au cours de ${coursResume} est confirmée..."
coursResume = coursInfos.map(ci => villeLabel + ' — ' + niveauLabel).join(' & ')
Cours boxes : coursInfos.map() → une div.cours-box par cours
Titre : "VOTRE INSCRIPTION CONFIRMÉE" (1 cours) ou "COURS 1 — PARIS DÉBUTANTS" (2 cours)
Par cours : Cours · Prochain cours · Heure · Lieu · Rôle (badge) · ✓ Inscrit·e
Horaires : tev_params_${ville}_${saison}.horaires[niveau] (Supabase → parametres)
Adresse : tev_params_${ville}_${saison}.adresse (Supabase → parametres)
Prochain cours : première date >= aujourd'hui dans tev_cours_dates.${ville} (Supabase → parametres)
PWA : Bloc violet iPhone/Android → app.tangoetvous.fr
Livrets : Un bouton par (ville, niveau) distinct dans coursInfos
URL : tev_params_${ville}_${saison}.livret.url_deb ou .url_int selon niveau (Supabase → parametres)
Bouton omis si URL vide
J+7 : Déclenche le cron P1 (espace élève) 7 jours plus tard

I-relance — Rappel avant la rentrée (cron 22 août)

POST /api/cron/relance-inscription (header X-Cron-Secret) · workflow relance-inscription.yml · cron 0 8 22 8 * + déclenchement manuel
Cible : inscriptions_cours?statut=eq.attente_paiement&saison=eq.<saison à venir>
⚠️ Les statuts demande (Att. Valid.) sont EXCLUS — ces personnes ne peuvent pas encore payer. Fiches sans email ignorées (comptées dans sansEmail).
Saison : calculée côté serveur (sept→août), ou body.saison au déclenchement manuel
Anti-doublon : aucun marqueur (choix admin) — une personne qui règle passe en inscrit et sort de la cible ; rejouer la tâche = 2ᵉ relance sûre
Sujet : La rentrée approche — finalisez votre inscription au tango
Preheader : "La rentree approche - finalisez votre inscription au tango sur AssoConnect"
Bandeau : Bleu #e3f2fd · 17 px — « 🗓 Votre place vous attend — finalisez votre inscription » (couple : « Vos places en duo vous attendent »)
Intro : 16,5 px — « La rentrée approche ! Votre place… n'est pas encore finalisée sur AssoConnect » (couple : « Vos places…, avec ${partenaire}, sont réservées »)
Cours box : Cours · Prochain cours · Heure · Lieu · Rôle · Partenaire (si couple) — titre « Votre inscription »
Encadré violet : couple uniquement — chacun doit s'inscrire séparément avec une adresse email différente
L'avertissement équivalent du bloc « Quelques précisions » a été retiré ici pour éviter le doublon (I01/I02 le conservent).
Bouton AssoConnect : Or → tev_liens_assoconnect[saison].cours (repli : .cours à la racine)
Encadré pourboire : Rouge — identique à I01/I02
acNote : « Votre place sera définitivement réservée une fois l'inscription et le premier paiement effectués. » 12px/#888
Quelques précisions : bouton jaune « J'adhère » + CB 1×/3× · espèces · chèque
Sorano : si ville='vincennes' → encadré jaune + bouton si _getSoranoLien(saison) renvoie un lien
Livret : tev_params_${ville}_${saison}.livret.url_deb | url_int
Signature : signEleve — « À très bientôt sur la piste ! »
Horaires / adresse : tev_params_${ville}_${saison}.horaires (clés plates deb/deb_fin/int/int_fin) et .adresse
Prochain cours : 1ʳᵉ date ≥ aujourd'hui dans tev_cours_dates[ville]
⚠️ Tout est relu côté serveur : contrairement à I01/I02 qui reçoivent leurs données du navigateur admin, le cron ne reçoit rien du client — il relit tous les paramètres au moment de l'envoi
Preview : preview-relance-inscription-v1.html — générée depuis le code par node outils/generer-preview-relance.js
