C2 / C2b — Renouvellement sans payer

POST /api/notify/carte-renouvellement (sans auth)
Déclencheurs :
  • C2 — l'élève clique « ↻ Renouveler sans payer pour l'instant » dans son espace (index.html renewCarteSelf). Branché le 2026-08-17 : jusque-là aucun appel n'était fait, donc ni email ni notification.
  • C2b — l'admin renouvelle en choisissant « Non payé » (Cartes → Détails → ↻ Renouveler)
  • ⚠️ Jamais envoyé quand l'admin choisit « Payé » : la modale de paiement enchaîne et c'est C3 qui part (drapeau sansEmailRenouv, admin.html).
Body : { email, prenom, restants, source ('eleve'|'admin'), liensAssoConnect }
⚠️ restants = taille de la NOUVELLE carte, pas un solde : le worker en fait _tailleC = restants > 0 ? restants : 10.
Sujet : C2 « Nouvelle carte ouverte — pensez à finaliser votre paiement » · C2b « Votre carte de ${taille} cours a été renouvelée — paiement à finaliser »
Preheader : "Nouvelle carte de cours creee - pensez a finaliser votre paiement sur AssoConnect" (identique dans les deux cas)
Bandeau : Orange ⚠️ « Nouvelle carte créée — finalisez votre paiement »
Carte-box : deux lignes seulement — « Cours utilisés 0/${taille} » et « Statut paiement ⚠️ Non payée ». Ni cours, ni saison : le worker ne les reçoit pas.
Bouton AssoConnect : Or → valeur reçue dans liensAssoConnect. Côté élève : _lienRenouvAC() lit tev_liens_assoconnect[saison].renouv avec repli sur le défaut de la saison. ⚠️ Côté admin, la valeur envoyée est aujourd'hui '#' — le bouton de C2b ne mène nulle part.
Notif admin : notifications — « ↻ Carte renouvelée [par l'admin ]sans payer — Prénom · ⚠️ Paiement en attente » → Cartes
Notif élève : notifications_eleve — « ⚠️ Nouvelle carte créée — pensez à finaliser votre paiement »
Push OS élève : « ⚠️ Nouvelle carte créée — pensez à finaliser votre paiement »

C-pay / C3 — Paiement de la carte enregistré

POST /api/notify/carte-paiement (JWT admin)
Déclencheurs :
  • C-pay — l'admin bascule la pastille « ⚠️ Non payée » d'une carte existante, puis valide le montant
  • C3 — parcours « ↻ Renouveler → Payé → ✓ Enregistrer le paiement ». Mis en place le 2026-08-17 : auparavant ce parcours n'envoyait pas de confirmation, mais C2b, qui réclamait un règlement à quelqu'un en train de payer.
Body : { email, prenom, nom, montant, modePaiement, datePaiement, utilises, restants, expiration, renouvellement? }
Condition C3 : renouvellement === true — posé par admin.html quand la modale de paiement a été ouverte à la suite d'un renouvellement. Absent → C-pay strictement inchangé.
Sujet : C-pay « Votre paiement a bien été enregistré — Tango & Vous » · C3 « Votre carte de ${taille} cours a été renouvelée — Tango & Vous »
Preheader : C-pay "Votre paiement a ete enregistre - votre carte de cours est active" · C3 "Votre carte de cours a ete renouvelee - le reglement est enregistre"
Bandeau : Vert — C-pay « ✓ Paiement enregistré — votre carte est active » · C3 « ✓ Votre carte a été renouvelée »
Carte-box : titre « VOTRE CARTE DE ${taille} COURS » (C3 : « NOUVELLE CARTE DE ${taille} COURS »), puis Paiement enregistré (montant + mode) · Date · Cours utilisés · Cours restants · Valide jusqu'au. Ni cours, ni saison : non transmis.
⚠️ Expiration : reçue dans le body (expiration), calculée côté admin depuis le premier cours pointé — le worker ne la recalcule pas. Ligne masquée si le champ est vide (cas d'une carte fraîchement renouvelée, jamais pointée).
Bouton : Or « Accéder à mon espace élève → » → app.tangoetvous.fr
Notif élève : notifications_eleve — « ✓ Paiement enregistré · Votre carte est active » (C3 : « ↻ Nouvelle carte active · Paiement enregistré »)

C4 — Fin de saison J+1 (lendemain dernier cours Paris juin)

POST /api/cron/fin-saison-c4 (X-Cron-Secret)
Déclencheur : Cron 8h UTC 20-30 juin · handler vérifie si hier = dernière date Paris de juin dans tev_cours_dates.paris · sinon {skipped:true}
Force : body {"force":true} → bypass la vérification de date (via workflow_dispatch)
Filtre élèves : quadruple condition — carte_restants > 0 ET carte_statut IN ('Active','Nouvelle carte') ET carte_paye = true ET carte non expirée (carte_expiration >= aujourd'hui, ou nulle), puis croisement avec _emailsInscritsActifs() — au moins une inscription statut='inscrit' dans la saison. ⚠️ Ce croisement exclut les cartes supprimées dont carte_statut serait resté désynchronisé.
Sujet : 📅 Il vous reste ${restants} cours — reportez votre carte sur la saison ${saiNext}
Preheader : "Il vous reste des cours sur votre carte - pre-inscrivez-vous pour la saison prochaine"
saiNext : sai = mo>=9 ? yr+'-'+(yr+1) : (yr-1)+'-'+yr ; saiNext = une saison plus tard — jamais hardcodé
anneeFin : parseInt(sai.split('-')[1]) — jamais hardcodé
Bouton : "Reportez votre carte → Réglez votre adhésion de la saison prochaine" · href = tev_liens_assoconnect[saiNext].cours (Paramètres → Tango Paris → Liens AssoConnect → "Inscription tango (formulaire cours)")
Notif élève : notifications_eleve — "📅 Il vous reste ${restants} cours — reportez votre carte sur la saison ${saiNext}"
Push OS élève : "📅 Il vous reste ${restants} cours — reportez-les sur la saison ${saiNext}"
⚠️ Correctif 2026-08-17 : ce push ne partait jamais — le handler utilisait une table de jetons FCM qu'il ne déclarait pas, l'erreur étant avalée par son try/catch. L'email, lui, partait normalement.
⚠️ Toutes les années et saisons dynamiques — jamais hardcodées

D-msg — Push discussion (nouvelle discussion ou nouveau message)

POST /api/notify/discussion-nouvelle (JWT admin) · POST /api/notify/discussion-message (JWT admin)
Déclencheurs :
  • handleNotifyDiscussionNouvelle — Admin crée un fil de discussion vers un élève
  • handleNotifyDiscussionMessage — Admin envoie un message dans un fil existant
Email élève : Pas d'email — push OS uniquement + notification in-app (notifications_eleve)
Push OS élève : Via getFcmTokensForEmail(email, env.SUPABASE_SERVICE_KEY) + sendFcmPush(env, tokens, notif) — fire-and-forget
Push nouvelle disc. : { title:'Tango & Vous', body:'💬 Nouvelle discussion : ${titre}' }
Push nouveau msg : { title:'Tango & Vous', body:'💬 ${auteur} : ${extrait || titreLabel}' }
Notif in-app : notifications_eleve INSERT via REST anon — message identique au corps du push
⚠️ Pas d'email Brevo pour D-msg — le push et la notif in-app suffisent. Les destinataires sont des élèves existants avec la PWA installée.
