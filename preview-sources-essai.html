Actions élève via email — confirmer / annuler / reporter (RPC SECURITY DEFINER)

Routes worker :
  • GET /api/essai/confirmer?id=&token= → handleEssaiConfirmerAnnuler(action='confirmer')
  • GET /api/essai/annuler?id=&token= → handleEssaiConfirmerAnnuler(action='annuler')
  • GET /api/essai/reporter?id=&token= → handleEssaiConfirmerAnnuler(action='reporter')
Token HMAC : HMAC-SHA256(${id}:${email.toLowerCase()}, SUPABASE_ANON).slice(0,32)
Backend : RPC Supabase confirmer_annuler_essai(p_id, p_token, p_action, p_secret) — SECURITY DEFINER, bypass RLS, vérifie HMAC server-side avant UPDATE
Action confirmer : UPDATE presence_confirmee=true → page verte 👍 "Présence confirmée !"
Action annuler : soft-delete UPDATE statut='supprimé', statut_avant_suppression=v_row.statut (cohérent avec le bouton ✕ admin) → page rouge ✕ "Inscription annulée" + notif admin → la fiche apparaît grisée en bas du cours + dans l'onglet 🗑 Supprimés
Action reporter : même soft-delete que annuler → notif admin "↩ Report essai" → Response.redirect 302 vers /cours-essai.html
Idempotent (2ᵉ clic) : si statut='supprimé' déjà posé → retour {ok:true, already:true} sans UPDATE, sans notif. Annuler affiche "Déjà annulé", reporter redirige quand même vers le formulaire (UX).
Rétablir possible : via l'onglet 🗑 Supprimés admin → bouton 🔄 Rétablir → UPDATE statut = statut_avant_suppression || 'confirme' → la fiche revient au cours d'origine
Suppression définitive : via l'onglet 🗑 Supprimés → bouton 🗑 Définitif → modal confirmation → DELETE réel en DB (irréversible)
⚠️ Historique : initialement UPDATE statut='annulé' (fiche restait visible, aucun filtre) → DELETE direct (perte d'historique) → soft-delete actuel (équilibre : traçabilité + onglet dédié + restauration possible). Voir CLAUDE.md session 2026-05-23 (suite 4).
Pourquoi RPC : RLS sur inscriptions_essai bloque SELECT/UPDATE pour clé anon → PATCH direct échoue silencieusement (0 lignes affectées sans erreur HTTP) → "Inscription introuvable" affiché en boucle. SECURITY DEFINER + HMAC server-side = bypass contrôlé.

  • Sujet reporter : ↩ [Essai tango] Report essai — Nom · Date

  • Bandeau reporter (bleu) : "↩ L'élève va réserver une nouvelle date"
  • Encadré or : Nom · email (mailto) · tel (tel:) · Cours (Paris/Vincennes Déb/Inter) · Date
  • Bouton : "Ouvrir l'admin — Essai Tango →"
Canal 3 — Push OS admin : sendFcmPush(env, getFcmTokensAdmin(svcKey), {title:'Tango & Vous — Admin', body:'✕ Annulation essai — Nom · Date'}) — uniquement si FIREBASE_SERVICE_ACCOUNT configuré
Confirmer 👍 : aucune notif admin — seulement le badge 👍 sur la fiche élève dans admin (sous-onglets Pointage + Par date)
Dédoublonnage : si result.already=true → aucune notif envoyée (évite spam admin sur double-clic)
