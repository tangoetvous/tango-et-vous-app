Actions élève via email — confirmer / annuler / reporter (RPC SECURITY DEFINER)

Routes worker :
  • GET /api/essai/confirmer?id=&token= → handleEssaiConfirmerAnnuler(action='confirmer')
  • GET /api/essai/annuler?id=&token= → handleEssaiConfirmerAnnuler(action='annuler')
  • GET /api/essai/reporter?id=&token= → handleEssaiConfirmerAnnuler(action='reporter')
Token HMAC : HMAC-SHA256(${id}:${email.toLowerCase()}, SUPABASE_ANON).slice(0,32)
Backend : RPC Supabase confirmer_annuler_essai(p_id, p_token, p_action, p_secret) — SECURITY DEFINER, bypass RLS, vérifie HMAC server-side avant DELETE/UPDATE
Action confirmer : UPDATE presence_confirmee=true → page verte 👍 "Présence confirmée !"
Action annuler : DELETE FROM inscriptions_essai WHERE id=p_id (cohérent avec le bouton ✕ admin) → page rouge ✕ "Inscription annulée" + notif admin → la fiche disparaît immédiatement de Essai Tango
Action reporter : même DELETE que annuler → notif admin "↩ Report essai" → Response.redirect 302 vers /cours-essai.html
Idempotent (2ᵉ clic) : SELECT NOT FOUND → {ok:false, error:'introuvable'} → annuler affiche "Déjà annulé", reporter redirige quand même vers le formulaire (UX), confirmer renvoie 404 (cas pathologique)
⚠️ Pourquoi DELETE et pas UPDATE statut='annulé' : inscriptions_essai n'a pas de statut 'annulé' dans le workflow métier (valeurs utilisées : 'confirme', 'attente', 'demande'). L'admin (bouton ✕) fait un DELETE direct → cohérence + la fiche disparaît vraiment du tableau Essai Tango.
Pourquoi RPC : RLS sur inscriptions_essai bloque SELECT/UPDATE pour clé anon → PATCH direct échoue silencieusement (0 lignes affectées sans erreur HTTP) → "Inscription introuvable" affiché en boucle. SECURITY DEFINER + HMAC server-side = bypass contrôlé.

Notifications admin — Annuler / Reporter (essai tango)

Déclencheur : Élève clique ✕ Annuler ou ↩ Reporter depuis son email
Implémentation : Inline dans handleEssaiConfirmerAnnuler (worker.js) — fire and forget, ne bloque pas la réponse HTTP à l'élève
Canal 1 — Panel 🔔 admin : INSERT notifications type='essai_annule', message "✕ Annulation essai — Nom · Cours · Date" ou "↩ Report essai — ...", lien_tab='essai'
Canal 2 — Email Brevo : envoyé à tangoetvous@gmail.com
  • Sujet annul : ✕ [Essai tango] Annulation essai — Nom · Date
  • Sujet reporter : ↩ [Essai tango] Report essai — Nom · Date
  • Bandeau annul (rouge) : "✕ Place libérée — pensez à la liste d'attente"
  • Bandeau reporter (bleu) : "↩ L'élève va réserver une nouvelle date"
  • Encadré or : Nom · email (mailto) · tel (tel:) · Cours (Paris/Vincennes Déb/Inter) · Date
  • Bouton : "Ouvrir l'admin — Essai Tango →"
Canal 3 — Push OS admin : sendFcmPush(env, getFcmTokensAdmin(svcKey), {title:'Tango & Vous — Admin', body:'✕ Annulation essai — Nom · Date'}) — uniquement si FIREBASE_SERVICE_ACCOUNT configuré
Confirmer 👍 : aucune notif admin — seulement le badge 👍 sur la fiche élève dans admin (sous-onglets Pointage + Par date)
Dédoublonnage : si result.already=true → aucune notif envoyée (évite spam admin sur double-clic)
